Roadmap

An honest status report: what's live and fully working today, what's built but needs a setup step, and what's intentionally not built yet — plus what each of those would actually require.

✅ Live now (no setup needed)

Everything below runs entirely in the browser — no account, no backend, no API keys.

  • 10 room-by-room guides + Plants & Trees guide
  • Room-by-Room Checker + Vastu Score Card
  • Interactive Compass (incl. live device-compass mode)
  • Vastu Health Dashboard
  • Vastu Advisor (rule-based personalization)
  • Daily Vastu Tips
  • Remedies Without Demolition library
  • Plot Selection Tool
  • Rent House Checker
  • Vastu for Offices
  • Product Guide (educational, no shop/links)
  • Gamification badges (My Progress)

🛠️ Built, needs a one-time setup

AI Consultant (open-ended chat)

UI and backend code are complete (consultant.html + api/consult.js). Needs an ANTHROPIC_API_KEY or OPENAI_API_KEY added in Vercel's environment variables, then a redeploy. See the README.

Floor Plan Analysis

Same setup as the AI Consultant (floor-plan.html + api/analyze-floorplan.js) — both providers support image input, so no extra config beyond the key. Expect this to be genuinely hit-or-miss on messy hand-drawn sketches; it's an assistive first pass, not a certified survey.

🗺️ Not built — and what it would take

Camera-based AR overlay

True AR (highlighting "place bed here" over a live camera view) needs a native AR framework (ARKit/ARCore) or WebXR with careful device testing — not something reliably buildable or verifiable without physical devices. The Interactive Compass's live mode is the browser-feasible middle ground.

Muhurat Calendar with real dates

Needs a real Panchang/astronomical data source or paid API — without one, "auspicious dates" would just be invented. Better to integrate a proper data provider than fake it.

Community (before/after photos, Q&A)

Needs user accounts, a database, image storage, and moderation — a genuine backend application, not a static site.

Professional tier (multi-property, branded PDF reports, client management)

Needs auth, a database per professional account, and a PDF generation pipeline — all backend work.

Payments (Razorpay / Stripe)

Needs a merchant account in your name and a checkout integration — can be added once there's something to actually gate behind a paywall.

Native mobile app (Flutter)

A different platform entirely — separate codebase, app store accounts, and a mobile build toolchain. This site works as a mobile-friendly website today (and can be "installed" from the browser's share menu), which covers a lot of the same ground without a rewrite.

Full regional language translations

Hindi, Marathi, Tamil, Telugu, Kannada, Bengali, and Gujarati translations of every page are a large content effort best tackled deliberately, ideally with a native speaker reviewing the traditional terminology — happy to start with one language if you want to prioritize it.
